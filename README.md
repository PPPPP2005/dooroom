# DooRoom – ระบบเช็กชื่อเข้าห้องเรียน (โหมดข้อมูลจำลอง / Mock)

เวอร์ชันนี้ **ตัด Firebase, Database และ Backend ออกชั่วคราว** ทุกอย่างทำงานในแอปเดียวด้วยข้อมูลจำลอง
เก็บใน `AsyncStorage` (บนเว็บ = `localStorage` ของเบราว์เซอร์) โครงสร้างยังเป็น **React Native + Expo Router (Expo SDK 57)**
รันได้ทั้งเว็บ, iOS, Android

## เริ่มใช้งาน

ต้องมี Node.js 22.13 ขึ้นไป

```bash
npm install
npm run setup        # ติดตั้งแพ็กเกจของ Expo ให้ตรงเวอร์ชัน SDK (expo install)
npx expo start --clear
```

จากนั้นกด `w` เปิดบนเว็บ หรือสแกน QR ของ Expo ด้วยแอป Expo Go บนมือถือ

## บัญชีทดลอง

หน้าเข้าสู่ระบบมีปุ่มลัด 3 บทบาท หรือกรอกเอง:

| บทบาท | อีเมล | รหัสผ่าน |
|---|---|---|
| นักศึกษา | student1@doroom.test (ถึง student8) | student123 |
| อาจารย์ | teacher1@doroom.test, teacher2@doroom.test | teacher123 |
| ผู้ดูแลระบบ | admin@doroom.test | admin123 |

สมัครนักศึกษาใหม่ได้จากหน้าสมัครสมาชิก

## ฟังก์ชันที่ใช้ได้

- **เข้าสู่ระบบ 3 บทบาท** – แต่ละบทบาทเห็นเฉพาะเมนูของตัวเอง จำการล็อกอินไว้ในเบราว์เซอร์
- **ตารางเรียน (นักศึกษา) / ตารางสอน (อาจารย์)** – แยกตามวัน ไฮไลต์วันนี้ แสดงป้ายย้ายห้อง
- **เปิดเช็กชื่อ + QR** – อาจารย์กด "เปิดเช็กชื่อคาบนี้" ได้ QR (`doroom:<sessionId>:<token>:<scheduleId>`)
- **สแกน QR ด้วยกล้อง** – มือถือใช้ `expo-camera`, เว็บใช้กล้องเบราว์เซอร์ + jsQR/BarcodeDetector
  มีช่อง "วางรหัส QR" และปุ่ม "สแกนจำลอง" สำรองไว้ทดสอบบนเครื่องเดียว
- **ตรวจความถูกต้อง** – ไม่ได้ลงทะเบียนวิชา (`wrong_room_or_subject`), คาบปิดแล้ว (`wrong_time`), QR ผิด (`invalid_qr`)
  พร้อมแจ้งเตือนให้นักศึกษาว่าตอนนี้ควรเรียนอะไรที่ห้องไหน
- **แก้สถานะ มา/สาย/ขาด/ลา** รายคน และปิดคาบ (คนที่ยังไม่เช็กจะเป็นขาด)
- **ประวัติการเข้าเรียน** – นักศึกษา (สรุปต่อวิชา + รายการ), อาจารย์ (ประวัติคาบ/แก้ย้อนหลัง), แอดมิน (ทั้งระบบ)
- **รายงานสรุป** (แอดมิน) – มา/สาย/ขาด/ลา และ % เข้าเรียน กรองตามวิชา/ช่วงวันที่ ดาวน์โหลด CSV (เปิดใน Excel ได้ ภาษาไทยไม่เพี้ยน)
- **ประกาศ / ย้ายห้อง** (อาจารย์) – แจ้งนักศึกษาที่ลงทะเบียนวิชานั้น
- **เพิ่ม / แก้ไข / ลบ** (แอดมิน) – ผู้ใช้, รายวิชา, ห้องเรียน, ตารางเรียน (กันห้อง/อาจารย์ชนเวลา), การลงทะเบียน
- **ประวัติการใช้งาน (log)** และปุ่ม **รีเซ็ตข้อมูลจำลอง** ที่หน้าแอดมิน

## โหมดเดโม (`src/lib/config.js`)

`STRICT_TIME = false` (ค่าเริ่มต้น) → เปิดเช็กชื่อได้ทุกคาบและสแกนได้ทุกวัน/เวลา เพื่อทดสอบได้ตลอด
ตั้งเป็น `true` เพื่อใช้กฎเหมือนระบบจริง (ต้องเป็นวันของคาบ และอยู่ในช่วงเริ่ม −15 นาที ถึงจบคาบ; สายเมื่อเกิน 15 นาทีหลังเริ่ม)

## ข้อควรรู้

- **ข้อมูลอยู่ในเครื่อง/เบราว์เซอร์นั้น ๆ เท่านั้น** ไม่ซิงก์ข้ามอุปกรณ์ และหายเมื่อล้างข้อมูลเบราว์เซอร์
  ข้อมูลตัวอย่าง (ผู้ใช้/วิชา/ตาราง) ใช้ ID ชุดเดียวกันทุกเครื่อง ดังนั้น QR ที่อาจารย์สร้างบนคอมพิวเตอร์
  สามารถสแกนด้วยมือถืออีกเครื่องได้ (มือถือจะบันทึกผลเช็กชื่อไว้ในเครื่องมือถือเอง ไม่ไปโผล่ในรายชื่อของอาจารย์)
- **กล้องบนเว็บ** เบราว์เซอร์อนุญาตเฉพาะ `https://` หรือ `http://localhost` — ถ้าจะเปิดเว็บบนมือถือให้ deploy ผ่าน HTTPS
  (`npm run export:web` แล้วอัปโหลดโฟลเดอร์ `dist/` ไปที่ Netlify/Vercel/GitHub Pages) หรือใช้ Expo Go ซึ่งกล้องใช้ได้เลย
- รหัสผ่านในข้อมูลจำลองเก็บเป็นข้อความธรรมดา ห้ามนำไปใช้กับระบบจริง
- `Alert.alert` ใช้ไม่ได้บนเว็บ จึงมีตัวช่วย `src/lib/dialog.js` ที่ใช้ได้ทั้งเว็บและมือถือ

## โครงสร้างโปรเจกต์

```
dooroomapp/
├─ src/
│  ├─ app/                 Expo Router
│  │  ├─ (auth)/           login, register
│  │  ├─ student/          ตารางเรียน · สแกน QR · ประวัติ · แจ้งเตือน · บัญชี
│  │  ├─ teacher/          ตารางสอน · ประวัติ/รายงาน · ประกาศ/ย้ายห้อง · session/[id] (QR + เช็กชื่อ)
│  │  └─ admin/            เมนูจัดการ · manage/[key] (CRUD) · attendance · report · logs
│  ├─ components/          ui, FormModal, QrScanner (+ .web.js สำหรับเว็บ)
│  └─ lib/
│     ├─ mock-db.js        ข้อมูลตัวอย่าง (seed) + เก็บลง AsyncStorage
│     ├─ mock-server.js    Backend จำลอง: ตรรกะเดียวกับ Express/Firestore เดิม
│     ├─ api.js            api.get/post/patch/del (หน้าตาเดิม แต่เรียก mock-server)
│     ├─ auth-context.js   ล็อกอิน/สมัคร/ออกจากระบบด้วยข้อมูลจำลอง
│     └─ config.js, time.js, format.js, dialog.js, download.js, admin-resources.js
└─ legacy/                 ของเดิมที่ตัดออกชั่วคราว (backend Express, เว็บแอดมิน HTML, firestore.rules, firebase.js, api.js/auth-context.js แบบ Firebase)
```

## ต่อ Backend / Firebase กลับมาภายหลัง

หน้าจอทุกหน้าเรียกผ่าน `api` และ `useAuth()` เท่านั้น จึงสลับได้ที่ 2 ไฟล์:

1. `src/lib/api.js` – แทนที่ด้วย `legacy/api.real.js.txt` (fetch ไปที่ `API_URL`)
2. `src/lib/auth-context.js` – แทนที่ด้วย `legacy/auth-context.firebase.js.txt` และคืน `firebase.js` + ค่า `EXPO_PUBLIC_*`

หมายเหตุ: หน้าแอดมินในแอปนี้ (`src/app/admin/*`) เรียก endpoint ชุดเดียวกับเว็บแอดมินเดิม
และมี endpoint เพิ่มที่ Backend จริงยังไม่มี: `GET /sessions/mine`, `GET /demo/open-sessions`, `POST /admin/reset`
และ QR มี `scheduleId` เป็นส่วนที่ 4 (Backend เดิมรับแค่ 3 ส่วน)
